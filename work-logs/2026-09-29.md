## CI のポーリングは要るか（ユーザーの質問。「なしでも良い」）
- 理由: マージ条件「CI の `ci` ジョブが緑」を満たしたことを、オーケストレータが知ってからマージするために、check-runs を curl で繰り返し読んでいた。完了時に 1 回起きる（wake）のと、マージ前に待つための仕組みで、必須ではない
- 根拠: リポジトリの設定（`GET /repos/d-kanai/ai-only-template`）: `allow_auto_merge: false`、`allow_merge_commit: true`、squash / rebase は無効、`delete_branch_on_merge: true`。GitHub の auto-merge を有効にすれば、required check（`ci`）が緑になった時点で GitHub 側が merge commit でマージし、ポーリングも wake も要らない
- 判断（ユーザー: ポーリング無しでよい）: 今後はポーリングしない。PR を作ったら、auto-merge が使えるなら `enable_pr_auto_merge`（GitHub MCP）を付けて終了、使えないなら次の人間のターンで CI を 1 回だけ確認してマージする。後始末（main の pull・ブランチ削除）は次の作業の最初に行う。手順（スキル `pr-flow`）の更新は Issue #80 の後に小さな PR で行う
- ユーザーへの依頼: リポジトリ設定 Settings → General → Pull Requests → 「Allow auto-merge」を ON（API の PATCH はクラウドのプロキシで書き込み不可のため、UI で）
