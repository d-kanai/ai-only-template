## アクセスログ（1 アクセス 1 行の JSON、5W1H）の情報設計を提案した（実装はまだ）
- 理由: ユーザーの依頼「アクセスログをアクセスごとに 1 行、5W1H が分かる JSON で出したい。まず情報を提案して」
- 根拠（Next.js 16.3.6 同梱ドキュメント `apps/frontend/node_modules/next/dist/docs`）: `proxy.md`（Proxy は Node.js runtime、`event.waitUntil` でレスポンス後のログ送信が可能。ただし応答前に動くので status / 所要時間は取れない）、`after.md`（Route Handler で `after()` により応答後に `headers()` / `cookies()` を読める。`next/server` なので backend からは使えない）、`instrumentation.md`（`onRequestError` はサーバエラーだけ）、`logging.md`（`incomingRequests` は開発時だけのコンソール出力で本番には効かない）。依存に pino / winston / morgan は無い
- 提案の骨子: backend の `apps/backend/shared/presentation/` にラッパー `withAccessLog(useCase, handler)` を置き、各 api ファイルの `export const GET = ...` で包む（Next に依存せず、status と所要時間を取れる。全 API に付いていることは `architecture.test.ts` の規則で機械的に強制）。出力は stdout に NDJSON 1 行（12-factor）。ページ閲覧まで要るなら `proxy.ts`（status / 所要時間なし）を後で足す
- ユーザーに確認する点: query / body の値を出すか（個人情報）、ページ閲覧も対象か、出力先は stdout だけでよいか、フィールド名はフラットか ECS 風のネストか
