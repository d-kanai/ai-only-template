# rule-review（コード・設計ルールのレビュー）

基準（対象外・証拠・重大度）はリポジトリ直下の `REVIEW.md`。最初に読む。
WHY この形（検出 → 1 件ずつ検証 → 重大度で報告）: Anthropic の code-review プラグインと Code Review と同じ。検出の段で「重大なものだけ」と絞ると見逃しが増えるので全部出させ、誤検知は別のコンテキストの検証で落とす（ADR `docs/adr/quality/20261002-rule-review-from-rules-tables.md`）。

## 手順
コピーして進める:
```
- [ ] 1. 差分と変更ファイルを取る
- [ ] 2. 観点の行を取り出す
- [ ] 3. 検出（rules のファイルごとに reviewer）
- [ ] 4. 検証（指摘 1 件ごとに reviewer）
- [ ] 5. 報告
```

1. **差分**: 引数が無ければ `base=$(git merge-base origin/main HEAD)` に対する `git diff $base`（未コミットも含む）と `git diff --name-only $base`、未追跡のファイルは `git ls-files --others --exclude-standard`。引数があれば、そのブランチ・コミット・patch を対象にする。差分が空なら「対象なし」で終える。
2. **観点の行**: `.claude/rules/code/*.md` のうち、フロントマターの `paths` の glob が変更ファイルのどれかに一致するものを選ぶ。選んだファイルごとに `grep -n '| レビュー |$' <file>` で行を取り出す（行番号つき。ID は `<file>:<行>`）。
   - 強制の列が `レビュー` でない行は使わない（CI が止める。REVIEW.md の「対象外」）。
   - 選んだファイルが 0 なら「観点なし」と報告して終える。
3. **検出**: 選んだ rules のファイルごとに `reviewer` サブエージェントを 1 つ、並列に起動する。渡すもの: 差分、そのファイルの観点の行（全文）、REVIEW.md。頼むこと:
   - 観点の行ごとに差分を見て、反している **可能性があるものを全部** 出す（絞らない）。
   - 1 件 = 観点の ID・WHAT の引用・コードの `file:line`・何が反しているか 1〜2 文・確信（0〜100）・重大度の案（🔴 / 🟡 / 🟣）。
   - 差分の外の既存のコードは 🟣。観点の行に結び付かない指摘は出さない。
4. **検証**: 3 の指摘 1 件ごとに、別の `reviewer` サブエージェントを並列に起動する（指摘を出したエージェントの文脈を持たないこと）。渡すもの: 指摘 1 件と観点の行 1 行と REVIEW.md。頼むこと: コードを開いて読み、指摘が成り立つか（keep / drop）と理由、重大度を 1 行で返す。
   - drop と、確信が低く根拠の `file:line` が示せないものは落とす。
5. **報告**: 次の形で返す（PR に書くときはこのまま）。
   ```
   ## rule-review: 🔴 <n> / 🟡 <n> / 🟣 <n>
   ### 🔴 Important
   - `<code file>:<line>` <何が反しているか>（観点 `<rules file>:<行>`「<WHAT の引用>」）
   ### 🟡 Nit（5 件まで）
   ### 🟣 Pre-existing
   ```
   - 指摘が 0 件なら「指摘なし」と、使った観点の行の数を書く。
   - 2 回目以降（指摘を直した後）は 🔴 だけ。

## 評価（skill を変えたとき）
`evals/` の patch を当てた差分でこの手順を通し、`evals/expected.md` の期待と比べる（手順は expected.md）。WHY: 観点を拾えているか・誤検知を出さないかは、実行して確かめないと分からない。
