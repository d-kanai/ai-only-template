## 質問への回答: `TodoDto` と `CreateTodoResponse` を分けている理由
- 理由: ユーザーの質問「なぜ 2 つの名前に分けている？ `CreateTodoResponse` に統一でもいい」。
- 根拠（コードの確認）: `list-todos.api.ts` のコメントに「1 API = 1 ファイルで契約（リクエスト / レスポンスの形）を同じファイルで読めるようにする。TodoDto は他の *.api.ts にも同じ形で書く（共通の dto.ts を作らないのはユーザー判断）」。`TodoDto` は「Todo 1 件の形」で、`ListTodosResponse` が `{ todos: TodoDto[] }` と包むために要る。`XxxResponse` は API ごとの本文の契約名で、画面側（`apps/frontend_customer/features/todo/api/todo-api.ts`）は `CreateTodoResponse` / `GetTodoResponse` / `ListTodosResponse` / `UpdateTodoResponse` と `TodoDto`（`todo-item.tsx` の props）を import type している。create / get / update では 2 つが同じ形なので別名が冗長に見える。
- 結論: 統一するなら create / get / update の `TodoDto` 別名を消して `XxxResponse` を直接オブジェクト型にし、`TodoDto` は list-todos だけに残す（画面の `TodoDto` は list-todos から取る）案。実装はユーザーの指示があれば Issue にして行う（未実施）。
