## CodeQL と pnpm audit を CI に入れた（Issue #112）
- 理由: daiki が基盤整備の候補から #112 を選んだ（「1-6やって」）。CI は依存の既知の脆弱性とコードの脆弱性のパターンを検査していなかった。
- 根拠: `pnpm audit`（pnpm 12.7.0、2026-10-03 実測）は moderate 4 件（GHSA-67mh-4wv8-2f99 / GHSA-q8mj-m7cp-5q26 / GHSA-x5fp-wj9c-mxmx / GHSA-4mjr-xmp4-gh2g。qs など Stryker の推移的依存）、high 以上は 0 件。`pnpm audit --audit-level high` は終了コード 0、`--audit-level moderate` は 1。`pnpm-workspace.yaml` に `auditConfig.ignoreGhsas: [GHSA-x5fp-wj9c-mxmx]` を一時的に足すと「3 vulnerabilities found / 1 ignored」になった（確認後に戻した）。`minimumReleaseAgeExclude` は pnpm 本体（`strings`）に設定名があることだけを確かめた（効くかは未確認）。CodeQL の SHA は `git ls-remote --tags https://github.com/github/codeql-action` の `v4.38.2^{}` = `2892aa5…`（`v4^{}` と同じコミット）。codeql-action の README（v4）で、interpreted languages の build-mode は none だけ・`security-events: write` が要ることを確認。
- 判断: audit は ci ジョブ（required）の中で high 以上を失敗にする。CodeQL は advanced setup（`codeql.yml`）で javascript-typescript と actions。required status check に入れるかは CI の実績を見て決める（ADR `docs/adr/quality/20261003-security-scan-in-ci.md`。採用しなかった案も ADR）。
- 未確認: repo の Secret scanning / push protection と CodeQL の default setup の状態（セッションの `GH_TOKEN` では `security_and_analysis` が返らず、`code-scanning/default-setup` は 403）。daiki に Settings → Code security で見てもらう。CodeQL の所要時間（この PR の CI で見る）。
- 機械化: 縛れる（`rule-tests/github-actions.test.ts` の `auditsDependencies` / `scansWithCodeQL`。ci ジョブの audit の形と、CodeQL の init / analyze・言語・トリガーを検査する）。リポジトリの設定（secret scanning・default setup）は縛れない（セッションから読めない）。
