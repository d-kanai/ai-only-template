## セキュリティヘッダ（CSP / HSTS など）と CORS の方針を決めて設定した（Issue #106）
- 理由: daiki が棚卸しの残り（Issue #106）の実装を選んだ。応答にセキュリティヘッダが無く、CORS の方針も決めていなかった。
- 根拠: CSP の nonce の付け方と開発の 'unsafe-eval' は Next.js 16.3.6 同梱の `node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md` を読んで確認（要求の CSP ヘッダから Next が nonce を読み、自分のスクリプトに付ける）。Mantine の `ColorSchemeScript` が `nonce` を props で受けることは `@mantine/core` 9.6.3 の `ColorSchemeScript.d.ts`（`React.ComponentProps<'script'>`）で確認。E2E（`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium pnpm test:e2e`）で、文書の `<script>` の nonce がすべて CSP の nonce と一致し、要求ごとに nonce が変わり、JS（`/_next/static`）と API の応答にも共通のヘッダが付き、CSP の下で Todo を追加でき、止めた読み込みが 0 件であることを確認。`DesignSystemHead` の nonce を外すと「Refused to execute inline script」で E2E が落ちることも確認した（fault injection）。
- 判断: 共通のヘッダは `next.config.ts` の `headers()`（Proxy の matcher が静的ファイルを除くため）、CSP は `proxy.ts` で画面にだけ付ける。style-src は Mantine の style 属性のため `'unsafe-inline'`。API は同じオリジンだけを前提にし、書き込みの Origin のホストが Host と違えば `ProblemResponse.wrap` が 403（`/problems/forbidden`・`request.origin.forbidden`）を返す。開発の判定に `NODE_ENV` が要り、`process.env` を直接読めない（Biome の `noProcessEnv`）ので `toolEnv.NODE_ENV` を足した。ADR `architecture/20261003-security-headers-and-same-origin-api.md`。
- 未確認: Cloud Run で Host がブラウザの Origin のホストと同じに保たれるか（保たれなければ画面からの書き込みが 403 になる）と、本番の応答にヘッダが付くこと。デプロイ先（stg）で画面から Todo を作れることと `curl -I` で確かめる。`next dev` で `'unsafe-eval'` が付き画面が動くことも未確認（E2E は `next start` だけ）。
- 機械化: 縛れる（値は `security-headers.test.ts`・`same-origin.test.ts`・`problem.test.ts`、付いていることと CSP の下で画面が動くことは E2E `apps/e2e/spec/security-headers.feature`）

## Issue #106 の reviewer の指摘を反映した（拡張子の付いたパスの CSP・OFREP の Origin・テストの抜け）
- 理由: reviewer の 🔴 2・🟡 5。(1) Proxy の matcher が拡張子の付いたパス（`.*\..*`）を除いていて、`/todo/abc.x` が CSP 無しの画面として 200 で返った。(2) OFREP の 2 本（POST）は `OfrepResponse.wrap` で包まれ、`SameOrigin` を通らなかった（ADR の「wrap はすべての api が通る」が事実と違った）。(3) `same-origin.test.ts` が `.host` → `.hostname` と `host === null ||` の削除の変異を見逃した。
- 根拠: (1) は reviewer が `next start` で実測。matcher から除外を外し、E2E に `/todo/abc.x` の CSP の確認を足した。public/ は無く、JS・CSS は `/_next/static` の下（`ls apps/frontend_customer/public` で無いことを確認）。(2) は `OfrepResponse.wrap` にも同じ判定を入れ、OFREP の失敗の形（errorCode GENERAL）の 403 を返す。(3) はポート付きの一致と「Origin が null で Host も無い」の 2 件を足し、2 つの変異がそれぞれ 1 件で落ちることを確かめた。
- 判断: ブラウザの文書の先読み（`purpose: prefetch`）の除外と、静的に出力される `_global-error` の画面の nonce は、限界として ADR と rules に書いて残した（今の画面は文書の先読みを出さず、`_global-error` が返る条件は未確認）。rules の「値」の行の強制はテストでは縛れないので「レビュー」に直した。
- 機械化: 縛れる（拡張子の付いたパスの CSP は E2E `security-headers.feature`、OFREP の拒否は `ofrep.test.ts`、判定の境界は `same-origin.test.ts`）
