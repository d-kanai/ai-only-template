# 単体テストのカバレッジは 4 指標とも 100% を必須にし、計測対象外はユーザーが決めたものに限る

- 日付: 2026-09-28
- 状態: 採用
- 関連: Issue #45 / PR #46 / `.claude/rules/testing.md` / `vitest.config.mts`

## 背景
テスト = 仕様（CLAUDE.md の原則 2）なので、テストの通らないコードを残したくなかった。ゲートを入れる前の計測では、4 指標とも 100% に届いていなかった（2026-09-28 の work-logs「単体テストのカバレッジゲート（100%）を追加（Issue #45）」）。

## 決定
- `pnpm test`（= CI の `ci` ジョブ）は Statements / Branches / Functions / Lines のどれかが 100% 未満なら失敗する。
- 計測対象外は、ルーティングだけの `app/` と設定ファイルなど、理由を書いてユーザーが決めたものだけ。届かない分は `/* v8 ignore */` で逃がさず、テストを足して埋める。

## 理由
- 100% 未満を許すと、どの未検証を許すかが毎回の判断になる。除外を「理由を書いた一覧」に限れば機械で止められる（CLAUDE.md の原則 7）。
- ユーザーの判断（「UT 100% にする。ignore ファイルは結果見て決めよう」→ `app/` と設定ファイルは対象外、残りはテストで埋める。同日の work-logs）。

## 採用しなかった案
- `/* v8 ignore */` で届かない分岐を除外する: 逃げ道になるので使わない（ユーザー判断）。

## 影響
- 良い点: 分岐を足したらテストも足すことが強制される。
- 悪い点: 分岐を通すだけのテストでも 100% になる。振る舞いの検証の強さは mutation testing で補う（quality/20260928-mutation-testing-daily-with-score-100.md）。
- 見直す条件: 記録に無い。
