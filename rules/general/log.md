# 作業ログルール

コードに残らない行動（設定変更・調査・判断など）を記録する。

- 置き場所: `logs/YYYY-MM-DD.md`（1日1ファイル）
- タイミング: タスクを終えるたびにAIが追記する。**調査や質問への回答だけで終わり、実装や設定変更に至らなかった場合も同じタイミングで追記する**（実装が無いと「タスク完了」の区切りが無く漏れやすいため、回答をユーザーに返す前に書く）。

## 記録対象
次はすべて記録する。後から同じ調査を繰り返したり、背景を知らずに変更してデグレしたりするのを防ぐため。

- 一次情報で裏どりした事実: 公式ドキュメントの制約や仕様、実測して分かった挙動、パッケージの版や公開日。情報源の URL か確認したコマンドを書く
- 比較検討の結論: 何と何を比べ、何を選び、なぜか。採用しなかった案も 1 行で残す
- ユーザーの判断: 提案に対する採否と、条件があればその内容
- 未確認のまま残した点: 何を確かめていないか、いつ確かめる予定か
- 実装に至らなかった調査: 「調べたが今回はやらない」と決めた理由
- 1項目のフォーマット:

```
## <やったこと>
- 理由: <なぜやったか>
- 根拠: <確認した情報源。未確認なら未確認と書く>
```
